## 2. 評価環境

**予選最終・リーダーボードとも、単一の NVIDIA L4 GPU（VRAM 24GB）で実施されます。** 推論モデルはこの環境で動作するよう設計する必要があります。

| 制約 | 上限 | 超過時 |
|---|---|---|
| 推論 1リクエスト（`/act`・`/reset`） | **10秒** | そのトラックは error 扱いの 0点 |
| **Track評価全体** | **1時間** | タイムアウト |
| サーバー起動（モデルロード含む） | 既定 120秒 | 評価不能として終了 |
| 提出ZIP | **20GB** | 受付不可 |
| 展開後 | 40GB | 検査で拒否 |

10秒制限は平均でも累積でもなく、**1回でも超えるとトラック全体が0点**です。Action chunkをサーバー内にキャッシュする構成では、実際に推論が走る「重い」リクエストだけが対象になります。

**Track評価全体の1時間上限は、10秒制限とは別の独立した制約です。** 総推論回数 × 1回あたりの時間がこの予算に収まる必要があるため、再計画間隔の設計に直接効きます。

評価環境は Ubuntu 22.04 + **Python 3.10** + osmesa レンダリング（配布Repo の `Dockerfile` / `setup.sh` が「本番採点環境と同一の構築手順」と明記）。

## 3. 評価指標とスコア

予選は **Track 1**（同一タスク・同一ドメイン・テクスチャ等の摂動）のみを評価します。

成功判定と衝突判定をゲートとし、重み付き正規化指標の積でスコアを計算します。

| カテゴリ | 指標 |
|---|---|
| タスク成功率 | Success Rate |
| **滑らかさ** | **ジャーク、SPARC、EEFの回転総量** |
| **実行効率** | **ステップ数、軌道の総距離** |
| 安全性 | 衝突判定 |

- 正規化式は**非公開**（各指標を 0〜1 の連続値へ変換）
- 重みも**非公開**。5つの重みの総和が 1
- 衝突ペナルティは [0, 1] のバイナリ
- Total Score がランキングに使われます

**成功率だけを最適化しても上位に行けません。** 滑らかさと実行効率が明示的にスコアへ入ります。ジャーク、SPARC、EEF回転総量、ステップ数、軌道総距離を悪化させる変更は、成功率が同じでもスコアを下げます。

### 成功判定

タスクのゴール条件を満たし、**かつ衝突が発生していない**場合のみ成功。

衝突は「操作対象以外の物体を動かしたか」で判定します。BDDL の `:obj_of_interest` を除く全物体について、初期位置からの変位（xyz 各軸の絶対値の和）を各ステップで監視し、**最大値が 1mm を超えた物体が1つでもあれば失敗**です。元の位置へ戻しても最大値で判定されるため失敗のままです。

### 参考スコア

配布学習例（SmolVLA LoRA Notebook）で学習したモデルのリーダーボード参考スコアは **Track1: 0.0633**。

## 4. 提出

提出先は **Omnicampus** の課題フォーム。zip 形式のみ、20GB 上限。

- **提出は1日1回まで**
- 回数は**採点が完了した時点**で消費されます。23:59 に提出して採点が翌日 0:30 に終わると、翌日分を消費します
- 採点には **10〜20分程度**かかる場合があります
- 推論の TimeOut やエラー落ちでは基本的に回数は消費されません
- アップロードにラグが生じるため、締切ギリギリの提出は避けること。**期限遅れへの救済措置はありません**
- 予選最終提出時のエラーにも救済措置はありません

まず一度提出して、提出できること自体を確認することが推奨されています。

## 5. Policy サーバー

`submission_template/policy_server.py` の `MyPolicy` を書き換えます。配布状態は**ランダムポリシー**で、そのままでも提出可能な形になっています。学習したモデルは書き換えないと反映されません。**この書き換え自体が課題の一部**です。

| メソッド | 役割 |
|---|---|
| `__init__` | `model_weights/` から学習済みモデルをロード |
| `get_action(obs)` | 観測を受け取り `(7,) float32` の action `[dx, dy, dz, droll, dpitch, dyaw, gripper]` を返す。1リクエスト10秒以内 |
| `reset(instruction="")` | エピソード開始時に言語指示を受け取り、内部状態（キャッシュ・履歴）をクリア |

書き換え不可の範囲は変更しないこと。

> 運営注意: policyサーバファイルに関する内容は課題の一部のため、他の参加者への質問・共有は控えるよう指示されています。運営からも回答されません。環境不具合が疑われる場合のみ問い合わせ可。

## 6. モデル・学習ルール

公開モデル、モデル構造、事前学習済み重み、tokenizer は利用可。ただし**参加者による独自学習が必須**で、独自学習要素が最終的な Action 生成に**実質的に寄与**する必要があります。

| 認められる | 認められない |
|---|---|
| LoRA、adapter 等の学習済みパラメータ | ファイル形式の変換のみ |
| 独自学習した Action head / decoder | モデル名・ファイル名の変更のみ |
| 独自学習した視覚・言語・状態統合モジュール | プロンプト・推論パラメータの変更のみ |
| | 公開重みを実質的に変更せずそのまま推論 |

## 7. データ利用ルール

利用可: 講座提供データ、公開データセット、独自収集・生成データ、シミュレータ、teleoperation、scripted policy、データ拡張、生成モデルによる生成。

必須: 出所、ライセンス、生成方法、使用目的を説明できること。

禁止: 評価結果を利用した追加学習、評価観測を保存しての後続学習、他参加者の非公開データ、利用権限のないデータ、法令・ライセンス違反データ。

## 8. 禁止事項

- 外部または手続き的なタスクレベルプランナー（CaPX等）
- タスク固有の有限状態機械
- ハードコードされた行動列
- scene ID、task ID、評価seed 等をキーとした行動テーブル
- 成功条件や報酬情報を直接参照するプランナー
- 評価環境専用の if 文による攻略処理
- 非公開タスクを識別する fingerprinting
- 学習済みモデルを実質的に使用しない fallback policy
- 評価中の外部ネットワークアクセス（評価クライアントとポリシーサーバ間の通信は許可）
- 評価環境へのアタック、ガードレール抵触

ZIP: 入れ子の圧縮ファイル、Zip bomb、シンボリック/ハードリンク、パストラバーサル、不要に難読化されたファイル。

判断に迷う手法は質問スプレッドシートで確認できます。

## 9. レポート

**PDF形式、2ページ以内**（日本語または英語）。Omnicampus のレポートフォームへ、8/17 23:59 まで。締切までなら複数回提出可。

記載必須:

- 学習・推論時の工夫点および試行錯誤
- モデル情報: モデル名/バージョン、ベースモデル名、ベース重みの入手元、使用した重みの version / revision / commit hash、提出チェックポイントのハッシュ値、モデル構成および推論方式、Action chunk の有無と chunk長
- 学習情報: 使用した学習データ（独自収集・生成はその概要）、データ件数/タスク数/エピソード数、学習方法、学習ステップ数または epoch 数、学習対象パラメータ、Full fine-tuning / LoRA / adapter の区分、主なハイパーパラメータ
- 権利関係: ベースモデルのライセンス、学習データのライセンス、提出物に含まれる第三者コードのライセンス

**レポート提出も予選選考要件です。** 提出忘れがあるとランキング上位でも本選へ出場できません。レポート記載内容と提出モデルに差があった場合、本選途中で失格の可能性があります。
